# 汇川 PLC 工具 v1.0.0

汇川（Inovance）H5U / H6E / Easy 系列 PLC 的轻量级工具。
核心功能：**PLC 运行/停止控制** 与 **.updown / .down 程序下载**，支持 **USB / 串口(RS485) / TCP** 三种连接通道，
所有日志带时间戳显示在界面文本框里。

界面分 **简易模式**（启动默认：一键下载，不用选通道）与 **完整模式**（手动选通道、Run/Stop、驱动维护），
右下角按钮随时切换。

> **版本号怎么改**：只需改 `INOVANCEPLCTool\Properties\AssemblyInfo.cs` 里的
> `[assembly: AssemblyFileVersion("1.0.0.0")]` 一行。窗口标题、简易模式标题右侧、完整界面左下角、
> 运行日志抬头、config.ini 注释**全部自动跟着变**（统一从 `AppInfo.cs` 读取）。

> ⚠ **测试版说明**：本工具目前仅在**汇川 Easy320** 上完成验证，**无法确认其他型号 PLC 的适用性**。
> 请勿在未经验证的机型上直接用于生产环境。
>
> USB 协议由 AutoShop 下载过程的 USB 报文抓包逆向还原，并已在 Easy320(H6E) / Easy301(H6ES) 实机验证。

## 一、功能一览

| 功能 | 说明 |
| --- | --- |
| **程序文件** | **统一入口**，只选一次即可：支持 `.updown` 与 `.down` 两种格式，USB / 串口 / TCP 三种通道共用。 |
| **下载 / 烧录** | **按「当前通道 + 文件格式」自动选择下发方式**（见下表），无需手动切换面板。 |

**下发方式自动分派表**：

| 文件格式 | USB 通道 | 串口 (RS485) | TCP 通道 |
| --- | --- | --- | --- |
| `.updown` | ✅ `PlcClient`（条目化下发，已验证） | ✅ `SerialBurnClient`（0x43 协议，**实测可烧、可运行**；点烧录时先弹一次确认框） | ✅ `TcpBurnClient`（12939 私有协议，按条目下发） |
| `.down` | ✅ `PlcClient`（同族格式，同样按条目下发） | ✅ `SerialBurnClient`（0x43 协议，整包原样下发，已验证） | ✅ `TcpBurnClient`（12939 私有协议，按条目下发） |

> `.down` 与 `.updown` 是**同一族格式**（`目录偏移 + TLV头 + 条目区`），条目名与内容**逐项一致**
> （实测 plccx.down 与 plccx.updown 均为 19 项、名称/大小/内容 100% 相同；两文件仅头部因魔数
> `PLC.DOWN`/`PLC.UPDOWN` 长度差 2 字节，其后全部字节逐一对齐）。
> 因此二者都可走 USB 条目化下发。
>
> **关于「串口能否烧 `.updown`」——已真机实测（2026-09-21，H6E @COM9 19200）**：
> 串口 0x43 协议的「文件声明」帧里不含魔数（body 前 8 字节是固定 `00×8`），PLC 在串口通道下
> **不校验文件头格式**，只把收到的字节流按 490 字节逐块存盘。实测把 `.updown`（50523B）当 `.down`
> 完整烧录：104 块全部 `06` ACK → 提交读回 `02 00 58 00` → **运行态回读 1（RUN OK）**，
> 与真 `.down`（提交读回 `02 00 5A 00`、同样 RUN OK）行为一致。
> 结论：**串口技术上也能烧 `.updown` 且能运行**；但官方支持矩阵仍是「串口↔`.down` / USB↔`.updown`」，
> 故工具把它做成「**可用但先弹确认框**」，而不是静默执行。
>
> **关于「TCP 通道」——协议已抓包破解（2026-09-21，H6E @192.168.1.88）**：
> PLC 的 **12939 端口**跑的是**私有无封装帧协议**（与串口 0x43 应用层同构），**不是 Modbus**；
> 502 端口才是标准 Modbus TCP。用 AutoShop 走网口成功下载程序，抓包（plc_tcp.pcap，186 包）还原出
> 完整时序，实现于 `TcpPlcProtocol` + `TcpBurnClient`，`.down`/`.updown` 均可按条目「声明+内容」下发。

| 功能 | 说明 |
| --- | --- |
| **连接通道** | 顶部固定区选择 **USB / 串口(RS485) / TCP**，按类型填写参数，点「打开 / 关闭」。 |
| **双视图切换** | 启动默认为**简易模式**（520×390：标题 + 「开始下载」+ 进度条 + **橙色测试版提示卡** + 更多功能；不含文件/通道选择与日志）；点「更多功能 ▸」切到完整界面并放大窗口，点「◂ 简易模式」切回。 |
| **一键下载（简易模式）** | 不用选通道也不用选文件：程序包取自 `config.ini`；**未连接则自动依次尝试 USB → 串口 → TCP**，已连接则直接复用。**试到 USB 时缺 libusb0 驱动会自动安装**（弹 UAC，装完需拔插一次 USB 线）。 |
| **RUN（运行）** | 让 PLC 转入 RUN 状态。**串口走 0x43 协议、TCP 走 12939 协议**（均非 USB 那套），写入后轮询回读确认并明确报「已确认/未确认」。 |
| **STOP（停止）** | 让 PLC 转入 STOP 状态。同样按当前通道自动选协议（串口 0x43 / TCP 12939）。 |
| **安装 / 修复驱动** | 强制释放并安装 H5U USB 驱动（libusb-win32），用于验证安装流程或修复损坏的驱动（仅 USB 通道需要）。 |
| **配置自动保存** | 通道、串口/TCP 参数、程序包路径、勾选项全部自动存到 exe 同级 `config.ini`，下次打开自动恢复。 |

界面还含：单一程序文件浏览入口、机型不匹配时「强制继续」勾选框、**运行态弹窗确认**（下载前后各一次，见使用步骤）、
随通道/格式变化的**下发方式提示**、整体进度条、带时间戳的日志文本框。

**内置程序目录（`Programs\`）**：通过「浏览...」选中的程序包会**自动拷贝一份到 exe 同级的 `Programs` 目录**，
并在配置里记成**相对路径**（`.\Programs\xxx.down`）。因此把 **exe + `Programs` 文件夹 + `config.ini`** 一起拷给
别人后，软件打开就能直接看到上次选好的程序，路径不会失效。

> **通道支持状态**：USB 通道功能完整（实机验证，走私有帧协议，`.updown` 与 `.down` 均可下发）；

> **串口(RS485) 通道** 支持 **RUN/STOP + `.down` / `.updown` 串口烧录**（0x43 协议已抓包破解并逐字节验证；
> 两种格式均已真机烧录验证可运行，`.updown` 会先弹确认框）；
> **TCP 通道** 支持 **RUN/STOP + `.down` / `.updown` 网口烧录**（12939 私有无封装帧协议，已由 AutoShop
> 网口下载抓包破解；端口填 **12939**，非 Modbus 502）。

   │  ├─ ModbusFrame.cs               ← Modbus 编解码：RTU(地址+CRC16) ⇄ TCP(MBAP) 互转
   │  ├─ SerialLink.cs                ← 串口通道（RS485/RS232，默认 **19200**-8-N-1；含 0x43 定长收帧）
   │  ├─ TcpLink.cs                   ← TCP 通道（默认 12939 私有帧模式；502 走标准 Modbus TCP）
   │  └─ TransportFactory.cs          ← 按 TransportOptions 创建对应通道
   └─ Usb\                            ← USB 通信层
      ├─ LibUsb0.cs                   ← libusb-win32 P/Invoke 与 DLL 预载

### 多通道架构说明

```
        ┌──────────────────────────────────────────┐
        │  PlcClient（业务：登录/状态/文件下发/下载）  │
        │  SerialBurnClient / TcpBurnClient（烧录）  │
        └───────────────────┬──────────────────────┘
                            │ 依赖 ITransport 接口
        ┌───────────────────┴──────────────────────┐
        │              ITransport                  │
        └───────┬───────────────┬──────────────────┘
                │               │                  │
           UsbLink         SerialLink          TcpLink
        （私有帧协议）   （0x43 私有协议）    （12939 私有帧；
                                           502 标准 Modbus TCP）
```

**为什么这样分层**：把「协议」与「载体」解耦。USB 走汇川私有帧协议；串口走 0x43 私有协议；
TCP 走 **12939 私有无封装帧协议**（三者应用层语义同构，仅封装不同）。因此业务层只依赖
`ITransport` 的「收发一帧」，各通道自带编解码，新增通道不影响其余通道。

> ⚠ 早期曾假设「TCP 与串口都是 Modbus」，**实测证明串口不是标准 Modbus**：功能码是汇川自定义的
> **0x43**（见第七节）。Modbus 相关代码仅作 TCP 通道预留，串口实际走 `SerialProtocol`。

> 注意：上面三个根文件（`libusb0.dll`、`libusb0_x64.dll`、`drivers.zip`）在编译时会被
> 作为**嵌入资源**打进 exe，运行时再按需释放到磁盘 / 用系统驱动。**分发时只需要最终的
> `INOVANCEPLCTool.exe`，不需要这些中间文件。**

## 四、构建（开发 / 重新生成）

用 **Visual Studio 2019/2022**（需装「.NET 桌面开发」工作负载）→ 打开 `INOVANCEPLCTool.sln`
→ 菜单 **生成 → 重新生成解决方案（Rebuild）**。

- 目标框架：`.NET Framework 4.7.2`
- 目标平台：`AnyCPU`，并在 csproj 中显式设置 `<Prefer32Bit>false</Prefer32Bit>`。
  这样在 64 位系统上以原生 64 位进程运行（加载内置的 64 位 libusb0.dll），
  在 32 位系统上以 32 位进程运行（加载内置的 32 位 libusb0.dll）。
- 生成产物：`INOVANCEPLCTool\bin\Debug\`（或 `Release\`）下的 `INOVANCEPLCTool.exe`。
  由于 libusb0.dll 与驱动包都已嵌入，exe 旁边**不应**出现独立的 `libusb0.dll` / `drivers\`
  （除非运行时首次自动释放驱动，见下）。

> 本仓库不含已编译的二进制，请自行在 VS 中生成。

## 五、使用步骤

### 两种模式（同一个窗口，按钮切换）

启动后默认进入 **简易模式**（窗口 520×390，只有下载相关的东西）：

| 模式 | 界面内容 | 进入方式 |
| --- | --- | --- |
| **简易模式** | 「开始下载」+ 进度条 + **橙色测试版提示卡**（醒目占满中部）（**不含文件选择、不含通道选择、不含日志区**） | 启动默认；点「◂ 简易模式」返回 |
| **完整模式** | 连接通道、RUN/STOP、程序文件选择、驱动维护、运行日志 | 点「更多功能 ▸」（窗口放大到 850×850） |

**测试版提示卡**（简易模式中部，最醒目的一块）写明三件事：
① 仅在汇川 **Easy320** 上完成下载验证；② H5U / H6E / Easy 系列其余机型**未逐一测试**、无法确认适用性；
③ 用于其他机型前，请先在**停机、可回滚**的场合试烧一次。卡片底部还实时显示「本次将下载：xxx.down（版本 …）」。

**简易模式怎么用（傻瓜式，不用理解通道区别）**：

1. 点大按钮「**开始下载**」；
2. 弹一个确认框（列出将下载的文件名、说明会自动连接/停机、测试版仅 Easy320 验证），点「确定」；
3. **没连接就自动连**：依次尝试 上次用成功的通道 → USB → 串口 → TCP，连上即下载；
   **已经连好就直接用**，不会重复连接（也就不会打断你手动建的连接）；
4. 连上后走与完整界面完全相同的下载流程（含下载前后运行态弹窗），进度条实时推进；
5. 若连接是本次自动建立的，下载完会自动断开、回到干净状态；若复用已有连接则保持不动。

#### ✅ 一键下载**包含** USB 驱动自动安装

自动试到 USB 通道时，会**先自检 libusb0 驱动，缺了自动装**（`TryConnectAny` 里 USB 分支第一件事就是
`DriverInstaller.EnsureDriver`），不需要先手动去「安装 / 修复驱动」。两条注意事项：

- **会弹 UAC**：安装需管理员权限，请在 UAC 窗口点「是」（否则本次 USB 尝试直接判失败，自动跳到串口/TCP）。
- **装完必须重新插拔 USB 线**：驱动刚落地时 PLC 还以原来的身份枚举，**拔插一次**让它以 libusb0 重新枚举，
  然后**再点一次「开始下载」**即可。工具会把这句话明确写进提示框，不会让你猜。
- 驱动**已装**的机器完全无感（只写一行日志「驱动已安装，无需操作」），不会打扰。

**程序包从哪来**：简易模式**不显示文件选择**，用的是 `config.ini` 里记住的那个程序
（首次使用请点「更多功能 ▸」在「程序文件」里选一次，之后自动回填）。
提示卡底部会显示「本次将下载：xxx.down（版本 1.0.0.1）」，让你确认这次要下的是哪个。
如果还没选过程序，点「开始下载」会提示，并**自动跳到完整界面**让你去选。

> **过程信息去哪看**：简易模式没有日志/状态区（保持界面极简），所有过程与报错
> 都写在完整界面的「运行日志」里——点「更多功能 ▸」即可看到，一条不漏。

### 完整模式步骤

1. **准备硬件**：连接 PLC 并上电。USB 直连用 USB 线；走 485 则用 USB 转 485 接到 PLC 的 485 口；
   走网口则确认 PLC 的 IP 与本机同网段。
2. **选择并打开通道**（界面顶部「连接通道」）：
   - **USB**：先**关闭 AutoShop**（libusb0 驱动对设备是**独占**的，AutoShop 正在联机时本工具无法打开 PLC）。
     选 USB → 点「打开」。首次在裸机上使用会自动弹 UAC 装驱动（见第 4 条）。
   - **串口 (RS485)**：选串口 → 选端口（无端口时点「刷新」）、波特率（默认 **19200**）、数据位/校验/停止位、从站地址 → 点「打开」。
   - **TCP (以太网)**：选 TCP → 填 IP（默认端口 **12939**）、单元 ID → 点「打开」。
     打开成功后本工具会做一次握手探测并显示机型与运行态。
   - **连接后的界面锁定（重要）**：一旦某个通道打开成功，
     **通道单选（USB / 串口 / TCP）与对应的参数面板（IP / 端口 / 波特率 / 从站地址 / 刷新串口）都会自动禁用**，
     防止连接过程中误改参数导致收发错乱；此时「打开」按钮也置灰。
     想换通道或改参数，**必须先点「关闭」断开当前连接**，解锁后再重新选。
3. **首次使用（裸机，仅 USB）**：若目标机未装过 libusb0 驱动，点「打开」时会**自动弹出 UAC 申请**，
   同意后由管理员 cmd 窗口完成驱动安装；装完日志会提示「请重新插拔 USB 线」。之后该机再无需装驱动。
4. **RUN / STOP**：点对应按钮即可。串口通道走 0x43 协议、TCP 通道走 12939 协议，
   写入后均轮询回读并明确报「已确认/未确认」。
5. **下载 / 烧录程序（统一入口，两种格式）**：
   1. 在「程序文件」区点「浏览...」选择程序包 —— **支持 `.updown` 和 `.down` 两种格式**；
      选好后按钮下方会实时提示「当前通道 + 该格式 → 走哪条下发路径」；
   2. 若机型与 PLC 不一致，可勾选「机型不匹配也继续」（风险自负）；
   3. 点「下载 / 烧录」——**工具按「当前通道 + 文件格式」自动选择下发方式**：

      | 场景 | 行为 |
      | --- | --- |
      | USB + `.updown` | 条目化下发（AutoShop 时序） |
      | USB + `.down` | 同样条目化下发（两种格式同族，条目 100% 一致） |
      | 串口 + `.down` | 0x43 协议整包烧录 |
      | 串口 + `.updown` | 0x43 协议整包烧录（**实测同样可运行**）；点烧录时先弹确认框提醒「非官方组合」 |
      | TCP + 任意 | 12939 协议按条目「声明+内容」下发；端口须填 12939 |

      **运行态由弹窗确认，不再需要手工勾选**（三个通道行为一致）：

      | 下载前 PLC 状态 | 工具行为 |
      | --- | --- |
      | **运行中** | 先弹窗「PLC处于运行状态，确定要将PLC停止并且继续操作吗？」<br>→ 点**取消**：整个下载中止，PLC 保持原样<br>→ 点**确定**：停机 → 下载 → 下载完再弹「PLC处于停止状态，确定要将PLC运行并且继续操作吗？」<br>&nbsp;&nbsp;&nbsp;&nbsp;· 点**确定** = 恢复运行；点**取消** = 保持停止（可稍后手动点「RUN 运行」） |
      | **停止中** | **全程不弹窗**，直接下载，下载完保持停止 |

   4. 观察进度条与日志；日志会逐帧打印收发（seq / 类型 / 原始 hex）便于排错。
      下载完成后工具会回读运行态并明确报「✓ 已确认进入运行态」或「✗ 仍处于停止态」。

> TCP 通道的烧录协议已由 AutoShop 网口下载抓包还原（12939 私有协议），`.down` / `.updown` 均可下发；
> 注意 **12939 是烧录端口，不是 Modbus**（502 才是标准 Modbus TCP）。

## 六、配置与内置程序目录（config.ini / Programs）

### 为什么要这两个东西

工具原本只输出一个 exe，**程序包必须每次手动重新选**。为了做到「配好一次，拷给别人就能直接用」，
引入了 exe 同级的两样东西：

```
INOVANCEPLCTool.exe      ← 主程序（仍然只需这一个文件就能跑）
config.ini               ← 自动生成，记录上次的参数（改完自动保存）
Programs\                ← 自动生成，存放内置的程序包
   └─ plccx.down
```

### 自动保存了哪些参数

| 分组 | 内容 |
| --- | --- |
| `[General]` | 程序包路径（**相对路径**）、上次用的通道、机型不匹配也继续 |
| `[Serial]` | 串口号、波特率、数据位、校验、停止位、从站地址 |
| `[Tcp]` | IP、端口、单元 ID |

**保存时机**：参数一改动就写盘，**没有「保存」按钮**（通道切换、下拉框选择、文本框失焦、勾选框点击、
浏览文件、刷新串口，都会触发保存）。

### 相对路径是怎么保证「拷走还能用」的

- 选中的程序包会被**自动拷贝**进 `Programs\`；
- 配置里存的是 **`.\Programs\plccx.down`** 这样的相对路径，而不是 `D:\xxx\Programs\plccx.down`；
- 软件启动时以 **exe 所在目录**为基准还原成绝对路径。

所以把整个文件夹移到 `E:\给张工的\PLC工具\` 或别的电脑上，路径依然指向**同目录下的 `Programs`**。

> 如果选中的程序包**不在** exe 目录下（比如直接从桌面选），则会**拷贝一份到 `Programs\`** 后使用；
> 拷贝失败时（如目标目录只读）会提示，但仍然用原路径完成本次下载，不阻断操作。

### 交付给别人时怎么拷

把这三样一起拷走即可（**必须整个文件夹一起拷，不能只拷 exe**）：

```
INOVANCEPLCTool.exe
config.ini
Programs\
```

首次在别人电脑上运行时会自动检查 .NET 4.7.2 与 libusb0 驱动（USB 通道）。

## 七、驱动与 DLL 的打包机制（关键设计）

工具把两层依赖都**编译进单个 exe**，做到「一个 exe 直接能用」：

1. **用户态 DLL（libusb0.dll）**：分 32 位 / 64 位两份嵌入资源。运行时按当前进程位数
   （`Environment.Is64BitProcess`）选对应那份释放到 exe 旁边（或 `%TEMP%` 回退）后 `LoadLibrary`，
   因此无论目标机是 32 位还是 64 位都能匹配加载。
2. **内核驱动（libusb0.sys）**：整套驱动包（`drivers.zip`，含 amd64/x86/ia64 三套内核驱动 +
   带签名的 `H5U_USB_Device.inf/.cat`）也作为嵌入资源编译进 exe。检测到未安装时释放到磁盘，
   生成 `install_driver.bat` 并用 `cmd.exe + runas` 提权执行（pnputil 安装 inf）。
   脚本已自动适配 Win7（`pnputil -i -a`）与 Win10+（`pnputil /add-driver ... /install`）两种语法。

详细排错与手动安装方法见同目录 **`驱动安装说明.txt`**。

## 八、通信协议简述

帧格式（全小端）：

```
+0  u16  len      整帧总长度（含本字段）
+2  u8   ver      恒为 0x01
+3  u8   cmd      命令类别（设备信息/软元件读写/文件/会话/会话控制）
+4  u32  seq      序列号，请求与应答一致
+8  u8   sub      子命令；在应答中复用为状态码
+9  u8   rsv      保留，恒为 0x00
+10 ...  payload
```

- 物理层：VID `0x0471` / PID `0xA531`，Bulk OUT = `0x02`，Bulk IN = `0x81`，最大包 512 字节。
- 运行状态写在软元件 `area=0x00, addr=0x0000`：`0x00`=停止，`0x01`=运行，
  `0x02`=进入下载模式，`0x03`=下载完成（触发校验/落盘）。
- 文件下发（`CMD_FILE=0x04`）：
  - 声明帧 `SUB_FILE_BEGIN=0x02`：payload = 12 字节属性(末4字节恒 0x0000A000) + u32 文件大小 + 文件名(NUL 结尾)。
  - 数据帧 `SUB_FILE_DATA=0x05`：payload = u32 偏移(=**块序号**) + u32 长度(=**本块字节数**) + 内容。
    按 40960 字节分块，末块取余数（详见「已知限制」中大文件分块说明，源自实机抓包）。
- 完整下载时序：停 → 资源查询 → 进下载模式 → 逐文件下发 → 写完成 → 提交 →
  恢复下载前状态。文件发送顺序参照 AutoShop 实际抓包顺序。

### 串口（RS485）烧录协议 —— 0x43 私有协议

> 来源：触摸屏串口直连 PLC 烧录全过程的 485 总线报文抓包（226 帧），逐帧 CRC 校验通过；
> 并已用「抓包数据流 == `.down` 文件」逐字节验证。**这不是标准 Modbus**（功能码 0x43）。
>
> ⚠️ 抓包文件的每行是**总线上的全部收发**（监控工具统一显示为"收"），一行里常把
> 「请求帧 + 应答帧」粘在一起，长帧还会折行。解析必须先按 CRC 逐帧切开，再按
> `(op, seq)` 配对成问答对，**不能当成单向数据流**。

帧格式（全小端）：

```
+0  u8   addr     站号，默认 0x01
+1  u8   0x43     功能码（固定；非 Modbus 的 0x03/0x10）
+2  u16  len      长度字段 = payload 长度 + 2（含 CRC 两字节）
+4  ...  payload
末尾 u16  CRC16   标准 Modbus 算法：初值 0xFFFF，多项式 0xA001，低字节在前
整帧总长 = 4 + len
```

载荷结构：

```
+0  u8   0x01               固定（版本/方向位）
+1  u8   op                 操作码：0x00=握手, 0x01=控制/状态, 0x04=文件传输
+2  u16  seq                序号（请求与应答一致，全局递增）
+4  u16  00 00              保留（抓包恒为 0x0000）
+6  u16  subop              子操作码
+8  ...  参数
```

子操作码与帧体：

| op | subop | 用途 | 帧体（subop 之后） |
| --- | --- | --- | --- |
| 01 | 0x0001 | 读软元件 | `addr(u16) | area(u8) | dtype=FF | count(u32)` |
| 01 | 0x0002 | 写软元件 | 同上 + `数据(count 字节)` |
| 04 | 0x0002 | 文件声明 | `00×8 | 块大小(u32=0x1EA) | 文件大小(u32) | 文件名 + NUL` |
| 04 | 0x0005 | 数据块 | `块号(u16) | 00 00 | 本块长度(u32) | 本块数据` |
| 任意 | 0x0005 | 应答·带数据 | 数据区 |
| 任意 | 0x0006 | 应答·完成 | 无 |

- **块大小 = 0x1EA = 490 字节**（完整块），末块 = 实际余数（例：50501 = 490×103 + 31，共 104 块）。
  末块帧体里的 u32 长度字段写**本块实际长度**（31），不是固定 490。
- **下发的数据 = `.down` 文件的完整原始字节流**（原样整文件下发，非"拼接各条目"）。
  已用抓包逐字节验证：50501 字节原样下发；仅头部摘要字段（tag 1005–1007）会因重复导出而变化，PLC 不作比对。
- 运行状态写在软元件 `addr=0x0000, area=0x00`（1 字节）：`0x00`=停止 / `0x01`=运行。
- 提交/落盘用软元件 `addr=0x0010, area=0x00`（4 字节）：写 `01 00 00 00` 后回读 `01 00 64 00`。
- **完整烧录时序**（seq 从 0 起递增，一问一答、请求与应答共用同一 seq）：

```
seq=0  握手        op=00 body= 01 00         ↔ 应答 05 00 + 设备信息(INOVANCE / H6E / 版本)
seq=1  读运行状态  op=01 01 00|00 00|00 FF|01 00 00 00
seq=2  写=停止     op=01 02 00|00 00|00 FF|01 00 00 00|00   ↔ 06
seq=3  回读确认    op=01 01 00|…             ↔ 05 00|00（0=已停）
seq=4  文件声明    op=04 02 00|00×8|EA 01 00 00|文件大小u32|"project/PLCProgram.down"\0
seq=5… 数据块 ×N   op=04 05 00|块号u16|00 00|本块长度u32|数据   ↔ 06 00|块号u16|00 00
seq=N  写 addr=0010 op=01 02 00|10 00|00 FF|04 00 00 00|01 00 00 00   （提交/落盘）↔ 06
seq=N+1 读 addr=0010 op=01 01 00|10 00|00 FF|04 00 00 00   ↔ 05 00|01 00 64 00
seq=N+2 读运行状态  op=01 01 00|00 00|00 FF|01 00 00 00
seq=N+3 写=运行     op=01 02 00|00 00|00 FF|01 00 00 00|01   （可选，恢复运行）↔ 06
```

> ⚠️ **六个致命坑**（前三在首版全踩了导致 PLC 完全无反应；第四导致"写停机"被误报失败；
> 第五、六导致"烧录完成后 PLC 不进入运行态"）：
> 1. **必须先握手**（seq=0），且全局 seq 从 0 开始；
> 2. **末块必须发实际余数长度**，帧体 u32 也写该长度，而不是固定 490（否则多发垃圾字节）；
> 3. **数据发完必须做 `addr=0x0010` 的写/读提交动作**，然后才写运行态。不提交则程序不落盘；
> 4. **应答类型必须按「单字节」读，不能按 u16**：
>    - 请求体 = `subop(u16) + 参数` —— 两字节；
>    - 应答体 = `类型(u8) + [数据]` —— **纯 ACK（Type=0x06）只有 1 个字节 `06`**。
>    - 早期把应答类型也当 u16 读，遇到纯 ACK（如 seq=2 写停机、所有数据块应答）时
>      第 2 字节越界取不到，被误判成 `0x0000` → 报「PLC 返回错误应答 … body=06」。
>    - 正解：`Type = Body.Length >= 1 ? Body[0] : 0`，合法值只有 `0x05`（带数据）/`0x06`（纯 ACK）。
> 5. **读「运行状态」必须读 1 字节**（`addr=0x0000, area=0x00, count=1`）：
>    - 读 1 字节 → `05 00 <状态>`，`01`=运行 / `00`=停止 —— **这才是真实运行态**；
>    - 读 2/4 字节 → 走另一种应答格式 `0F 00 40 00 …`，该值**恒定不变、不反映运行态**；
>    - 因此 `ReadRunState()` 永远按 1 字节读，**不要"顺手"改成 2 或 4 字节**。
> 6. **`RUN/STOP` 按钮必须按通道分派协议**：串口走 `SerialBurnClient`(0x43)、TCP 走 `TcpBurnClient`(12939)，
>    USB 走 `PlcClient`(私有帧)。早期串口也误用 `PlcClient`，导致点按钮"没反应"。

### 以太网（TCP）烧录协议 —— 12939 私有无封装帧

> 来源：用 AutoShop 走**网口成功下载程序**全过程的 Npcap 抓包（plc_tcp.pcap，186 包），
> 逐帧解析并已用「抓包内容 == `.down`/`.updown` 条目」逐字节比对
> （18 个内容帧中 15 个与包条目**完全一致**；另 3 个因抓包工程与本地 plccx.down 非同一份源码而有差异）。
>
> ⚠ **关键认知**：**烧录走 12939 端口，不是 Modbus**！PLC 的 **502 端口**才是标准 Modbus TCP
> （实测 FC3/FC4 正常应答）。若把 12939 当 Modbus 解析，会完全读不出长度。

帧格式（全小端）：

```
+0   u16  totalLen   整帧总字节数（含自身 2 字节）
+2   u8   0x01       固定
+3   u8   op         操作码
+4   u32  seq        序号（u32，全局递增）
+8   …    body       载荷（结构随 op 而定）
```

> 与串口 0x43 对比：**应用层语义同构，仅封装不同**——
> 串口 `[addr u8][0x43][len u16][payload][CRC16]`，payload = `01|op|seq(u16)|00 00|body`；
> TCP `[len u16][0x01][op][seq u32][body]`。即 TCP 去掉了站号/功能码/CRC，seq 扩为 u32，body 一模一样。

op 取值：`0x00` 握手 / `0x80` 登录 / `0x81` 会话 / `0x01` 软元件读写 / `0x04` 文件传输。

body 结构：

```
读软元件(op=01, subop=0001): 01 00 | addr(u16) | area(u8) | 0xFF | count(u32)
写软元件(op=01, subop=0002): 02 00 | addr(u16) | area(u8) | 0xFF | count(u32) | data
文件声明(op=04, subop=0002): 02 00 | 00 00 | tagA(u16) | tagB(u32) | chunk(u32=0x2710) | size(u32) | name\0
文件内容(op=04, subop=0005): 05 00 | blk(u16) | 00 00 | datalen(u32) | data
```

完整烧录时序：

```
seq=1..4  握手      op=00 body= 01 00
seq=5     登录      op=80 body= 01 00|"user0"+0xA7填充至64   ↔ 应答 op=81
seq=6     会话      op=81 body= 03 00|01 00 00 00
seq=7     读运行态  op=01 body= 01 00|00 00|00 FF|01 00 00 00
seq=10    写=停止   op=01 body= 02 00|00 00|00 FF|01 00 00 00|00
seq=22…   逐文件    op=04 声明(02 00|00 00|tagA|tagB|10000|size|name\0)
                   op=04 内容(05 00|blk|00 00|len|data)
末        提交      op=01 body= 02 00|10 00|00 FF|04 00 00 00|01 00 00 00
末        写=运行   op=01 body= 02 00|00 00|00 FF|01 00 00 00|01（可选）
```

> ⚠️ **三个坑**：
> 1. **帧首是 u16 长度前缀**（含自身 2 字节），不是 Modbus MBAP；`TcpLink.PrivateFrameMode`
>    在端口 = 12939 时自动启用。
> 2. **文件内容是逐条「声明 + 内容」下发**，不是把整包 `.down` 原样发（那是串口做法）；
>    内容为**未压缩原样**（抓包中 stprog.o 直接以 ELF 魔数 `7F 45 4C 46` 开头）。
> 3. **必须登录 + 会话**（`user0` 帧与 USB/串口完全一致），且发完文件要做 `addr=0x0010` 的提交动作。

## 九、`.down` 串口下载包格式

与 `.updown` 同一族结构（仅魔数与个别 tag 语义不同）：

```
+0   u32   目录区起始偏移（= 头部长度）
头部 TLV（从 +4 起紧排到 dirOff）：u32 tag + u16 长度 + 内容
    tag 1000 = 魔数 "PLC.DOWN"
    tag 1001 = 包格式版本   (如 "1.0.0.1")
    tag 1002 = PLC 机型     (如 "H6E")
    tag 1003 = 编译版本     (如 "0.16.0.0")
    tag 1004 = 19 字节二进制块（非计数）
目录/数据区：u16 名字长度 + 名字(UTF-8) + u32 数据长度 + 数据
文件尾：4 字节校验
```

## 十、注意事项与已知限制

- **必须关闭 AutoShop / 释放设备**：libusb0 独占设备，否则无法打开。
- **下载前后的运行态处理（三个通道统一）**：
  下载**前**先读 PLC 运行态 ——
  - 若**运行中**：弹窗「PLC处于运行状态，确定要将PLC停止并且继续操作吗？」。点取消则**整个下载中止**（PLC 不被动），
    点确定才停机 → 下载；下载**完成**后再弹窗「PLC处于停止状态，确定要将PLC运行并且继续操作吗？」，
    确定则恢复运行、取消则保持停止。
  - 若**停止中**：**全程不弹窗**，直接下载，烧完仍是停止态。

  即：是否恢复运行由**下载前的实际状态**自动决定，不再需要手工勾选。无论哪种情况，下载完都会**回读运行态确认**并写明结果。
- **大文件分块下载（已用实机抓包 + 真机下载双重验证）**：文件按 40960 字节（0xA000）分块下发，规则来自
  AutoShop 真实 USB 抓包（capture/usb_20260731_204645.jsonl，非猜测），并已用本工具在真实 PLC 上
  成功下载含 149KB `stprog.o` 的大程序（plccx.updown）端到端跑通：
  - 数据帧 offset 字段 = 块序号（0,1,2…），不是字节偏移；
  - 数据帧 length 字段 = 本块字节数，不是文件总大小；
  - 块大小固定 40960，最后一块取余数；单块帧长不超过 40978 字节，恒可装入单帧（u16 上限 0xFFFF）。
  - 物证：stprog.o(149500)=40960×3+26620、project.hcpp(66057)=40960+25097，各块 length 求和
    精确等于声明大小。文件不超过 40960 时退化为单帧（offset=0、length=文件大小）。
  - 进度条按块级实时推进，大文件不再一步跳到 100%。
  - **历史教训**：早期曾误用"offset=字节偏移 / length=块大小 / 32KB 块"的分块写法，写坏过一台 PLC
    （表现为下不进程序、需断电静置清态自愈）。任何分块/续传改动都必须先抓 AutoShop 真实报文核对，
    严禁凭猜实现。
- **协议分派（按通道自动选择，界面上只需选一个文件）**：
  - **USB 通道** → 走私有帧协议、**按条目下发**：`.updown` 与 `.down` **都支持**
    （两包同族、条目 100% 一致；分块 40960 字节，见上一条）。
  - **串口通道** → 走 0x43 私有协议、**整包原样下发**（490 字节分块）：`.down` 与 `.updown` **都支持**
    ——串口「文件声明」帧不含魔数，PLC 不校验文件头格式，实测 `.updown` 烧录后同样能进运行态；
    仅对 `.updown` 保留一次确认弹框（非官方组合提示）。
  - 结论：`.down` / `.updown` 走 USB 或串口都行。（`.down` 走串口、`.updown` 走 USB 是官方推荐路径，最稳。）
- **烧录流程必然经过停机**：三个通道在写数据前都要「先停机 → 写数据 → 再决定是否恢复运行」，
  这是协议要求，不是实现选择。是否恢复运行由**下载前读取到的实际状态**决定（运行中 → 下载完弹窗询问；
  停止中 → 全程不弹窗、保持停止），详见「使用步骤」第 5 条与「注意事项」中的运行态处理说明。
- **串口烧录的时序（已实机验证）**：站号 1，整包 50514 字节（104 块：103×490 + 末块 44B）
  **约 29 秒**完成（19200 下；9600 下约 58 秒），每块 PLC 应答约 300~550ms（PLC 写 flash 耗时）。
  工具按块发送并在每块后等应答，帧间隔 5ms、应答超时 3s。
- ⚠ **波特率随设备而异（重要）**：实测两台 H6E，一台是 **19200**、另一台是 **9600**；同一时刻**只有
  正确的那一档会有应答**，选错则首帧即超时（现象：PLC"完全没反应"）。工具默认取 **19200**，
  若「打开」后握手/首帧超时，**第一件事就是换波特率**（19200 ⇄ 9600），不要急着怀疑协议或接线。
- **TCP 通道（已支持烧录）**：界面支持 TCP 连接（顶部连接区，端口填 **12939**）。协议已由
  **AutoShop 网口下载抓包**还原为私有无封装帧（`TcpPlcProtocol` + `TcpBurnClient`），支持
  **RUN/STOP + `.down`/`.updown` 烧录**（按条目「声明 + 内容」下发，块大小 10000 字节）。
  注意：**12939 是烧录端口，不是 Modbus**；502 端口才是标准 Modbus TCP（用标准库可直接读写软元件）。
- **仅 Run/Stop/下载/烧录**：不含在线监控界面、工程上传、软元件批量编辑界面（底层 `ReadDevice/WriteDevice`
  已具备能力，可在此框架上扩展）。
- **程序包路径自动记忆 + 自动内置**：选过一次 `.down` / `.updown` 后，程序包会**自动拷贝到 exe 同目录的
  `Programs\`**，配置里只存**相对路径**（`.\Programs\xxx.down`），下次打开软件自动回填。整个文件夹
  拷到别的机器/别的盘符下依然能直接下载，不用重新选文件。详见「六、配置与内置程序目录」。
- **连接态互斥（界面约束）**：同一时刻只允许**一个**通道处于打开状态。
  「打开」成功后，通道单选与参数面板立即锁定（置灰）；**必须点「关闭」断开，才能切换通道或修改参数**。
  这条约束是刻意的——三个通道对应三套不同协议，连接中改参数会让已建立的会话与界面参数不一致，
  排查起来极难。底层实现见 `MainWindow.xaml.cs` 的 `UpdateUiLockState()` / `RbKind_Checked()`。
- **内核驱动需每台目标机装一次**：之后换不同版本的 exe 都通用（仅 USB 通道需要）。

## 十一、常见问题

- **「未找到 PLC」/「占用 USB 接口失败」**：检查 USB 线、PLC 上电；确认已在设备管理器看到
  `H5U USB Device`；确认 AutoShop 已断开或退出。
- **点了功能没弹 UAC、驱动没装上**：若本机已装过 AutoShop，驱动自检会认为「已安装」而跳过。
  此时点界面上的 **「安装 / 修复驱动」** 按钮强制走安装流程即可。
- **企业机装驱动报「第三方驱动被策略阻止」**：多为组策略限制，需联系 IT 放行，或手动以管理员
  运行释放出的 `INOVANCE_Drivers\install_driver.bat`。
- **装完驱动后仍连不上**：拔插一次 USB 线，让系统重新枚举设备。
- **串口打开失败「端口被占用」**：触摸屏/其它上位机抢了 COM 口，先关掉；或换一个 COM 口。
- **串口烧录首帧就超时**：**先换波特率试（19200 ⇄ 9600，两台实测设备分别是这两个值之一）**。
  再核对站号（默认 1）、数据位 8 / 无校验 / 停止位 1；PLC 若被别的主站占用也会不应答，先把触摸屏断开。
- **界面只有「开始下载」和进度条，找不到 Run/Stop、驱动安装**：说明当前在**简易模式**（启动默认）。
  点右下角「**更多功能 ▸**」即可切到完整界面，窗口会自动放大。
- **简易模式点「开始下载」报「连接失败：USB / 串口 / 网口都没能连上 PLC」**：日志里逐条写了每个通道失败的原因，
  按顺序排查：① USB 线/串口线/网线是否插好；② USB 通道是否已关闭 AutoShop（驱动独占）；
  ③ 串口波特率（**19200 ⇄ 9600**，两台实测设备分别是这两个值之一）；④ 网口 IP 与端口 12939。
  也可以点「更多功能」手动指定通道和参数后重试。
- **简易模式点「开始下载」提示「请先选择程序」**：简易模式**不显示文件选择框**（出于简洁考虑），
  程序包取自上次在完整界面选过的那个。按提示点「确定」会**自动跳到完整界面**，
  在「程序文件」里点「浏览...」选一次，之后回简易模式即可一键下载（下次打开也会自动记住）。
- **简易模式点「开始下载」弹 UAC**：正常现象——自动试到 USB 通道时在**装 libusb0 驱动**，点「是」即可。
  装完会提示「请拔插一次 USB 线后重新点下载」：**拔插一次再点「开始下载」**就通了
  （首次在新电脑上必然要走这一次，之后不再打扰）。若 UAC 点了「否」，本次 USB 尝试判失败，
  工具会自动跳到串口/TCP 继续试，不会卡住。
- **简易模式报「libusb0 驱动尚未就绪」**：驱动没装成。日志里会写明原因（UAC 被拒 / 脚本执行了但未注册），
  可点「更多功能」→「安装 / 修复驱动」重试，或按日志给出的路径手动右键「以管理员身份运行」那个 .bat。
- **点了「开始下载」但确认框点了取消**：不会做任何事，PLC 不受影响，可以重来。
- **简易模式点「开始下载」闪一下就结束、或弹出异常框**（如 `System.InvalidOperationException`）：
  这是**后台线程碰了界面控件**导致的（WPF 硬性限制：非 UI 线程不能读写控件）。
  本工具已把所有需要读界面的值（如「机型不匹配也继续」勾选、串口端口名）改为**先在 UI 线程取好再传给后台**，
  简易模式点下载时**后台线程不再直接访问任何控件**。若仍遇到，请把完整界面「运行日志」整段发给工程师。
- **通道单选点不动 / 参数框灰的**：说明当前通道已连接。这是刻意的锁定，点「关闭」断开后即可切换通道与改参数。
- **切通道时弹「通道已连接」**：同上。必须先断开，再切换（同一时刻只允许一条通道打开）。
- **下载时弹「PLC处于运行状态…」**：这是下载前的安全确认（PLC 正在运行，需先停机才能写程序）。
  点「取消」= 中止本次下载、PLC 不受影响；点「确定」= 停机并继续。
- **下载完弹「PLC处于停止状态…」**：问你是否把 PLC 恢复运行。点「取消」则保持停止，
  之后可随时用顶部「RUN 运行」按钮手动启动，不会丢程序。
- **串口烧录中途报「应答校验失败」**：多为干扰导致丢字节。工具按帧长 `4+len` 定长收帧并校验 CRC，
  已能自动吃掉部分噪声；若频繁失败，缩短串口线、远离变频器/伺服动力线，或降速重试。
